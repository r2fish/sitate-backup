# 元サーバーの /srv を名前つきの volume に置く(D-0185、D-0186、D-0189)

2026-11-04。作業指示書 5.1b の追加の完了条件。環境名 r2vol(終了後に down 済み)。

## 変更

- `test/env/accept/compose.yaml`: source に名前つきの volume を 1 つ(`sitate-acc-<名前>-source-srv` を `/srv` へ)。`/home` はコンテナの根に残す(D-0186。`/home` を別のマウントにすると手順 8 に `mount_parent` が出る)。合成データ(`gen-source-data`)・所有者・権限の付け方は変えない。
- `test/env/bin/accept-env.sh`: `up` は先頭で `down` を呼ぶので、up のたびに volume を作り直す。`down` は volume を名指しでも消す。`check` に「`/srv` がマウント点で `stat -f -c %T` が candidate の種類」の検査を足した。
- `test/mainpath/stage3_survey_test.go`: `checkSurveyDirsSupported`。`source survey` の `dirs[]` のうち label が `srv` のものがすべて `supported: true` かつ `fs_type` が candidate であることを第 3 段で確かめる(home は見ない)。
- 一度足した `declined` の `mount: /home` は外した(`stage2_test.go`・`stage3_rootchange_test.go`・`stage3_kinds_test.go` は元の形に戻っている)。

## fs の実測(起動した source の中)

Docker Desktop(macOS)の名前つき volume は ext4(spec 3.3 の candidate)。

## ACL

合成データの生成(`gen-source-data`)は ACL を付けない(ACL は製品の段 `acl` が付ける)。コンテナの根に置いていたときと同じく、付与前は基本の項目だけ。ext4 の volume で setfacl が効くことを実測した(ユーザー名 `nobody` はシステムの名前で、合成の値。秘密は無い)。

```
付与前 /srv/shopapp/config/app.conf: user::rw- group::r-- other::r--
setfacl -m u:nobody:r 後:            user::rw- user:nobody:r-- group::r-- mask::r-- other::r--
setfacl -x u:nobody で戻した
```

## 回ごとの作り直し

up → `/srv/MARK-r2vol` を書く → down → up で、印は無い(`ls: cannot access`、`/srv` は `kumoi-minato-share`・`shopapp` だけ)。down を挟まず up を重ねても(`/srv/MARK2`)印は無い。down 後は volume が残らない。

## 試験

- 赤: test/env を main の版(volume 無し)に戻して `make test-mainpath STAGE=3 NAME=r2vol` を流すと `dirs[] の srv の下が supported: true の candidate の種類でない: fs_type="overlay" supported=false`(2 件)で `--- FAIL: TestStage3MainPath (474.40s)`。
- `make test-mainpath STAGE=3 NAME=r2vol`: `--- PASS: TestStage3MainPath (302.93s)`、`/srv の下 2 件のうち supported: true でないもの 0 件`。
- `make test-mainpath STAGE=DB NAME=r2vol`(新しい環境): `--- PASS: TestStageDB (27.43s)`。
- 偽の LLM の通し(`make test-app-e2e`): add・lo・nocluster の 3 変種とも `rc=0`、A2・A6 の終了コード 0、`steps_passed` に 1〜13(手順 8 を含む)。偽の LLM の定義は `/srv/shopapp` を対象にするので、`/srv` の `mount_parent` は出ない。
- `accept-env.sh check r2vol --fast`: `集計: ok=50 FAIL=1`。FAIL は「リポジトリの追跡ファイルに生成した鍵…が無い」で、検査の文字列が accept-env.sh 自身に当たる既存の自己一致(今回の変更と無関係)。
