README の「審査員に見てもらう道」と「できないことと、これから」に書いた、提出日の実機の通しの記録。

- 書き方: 利用者がアプリの画面で見た結果と、横で手順を案内した提出文書のセッション(Claude Code)の記録から書き起こした。アプリの会話・核の出力・サーバーのログの写しは入れていない。実データ(業務アプリの DB の名前と中身)、サーバーの住所、鍵の値を含むため。

## 手順 9 の欠陥

- 観測: 期待する指紋は復元先の Ed25519 の鍵、見えた指紋は同じ復元先の ECDSA の鍵(復元先のコンソールで、ECDSA の公開鍵の指紋が見えた指紋と一致することを確かめた)。同じ呼び出しを 3 回して、見えた指紋は 3 回とも同じだった。
- 原因(コードで確かめた): 復元先のアダプタ(`adapters/restore-dest/ssh-host/conn.go`)は Ed25519 の鍵で指紋を固定する。続けて核が復元先へつなぐ接続(`internal/cli/ssh.go` の `Run`)は `HostKeyAlgorithms` を指定せず、golang.org/x/crypto の既定の順で ECDSA を先に選ぶ。試験の環境の復元先は Ed25519 の鍵だけを作る(`test/env/bin/accept-env.sh`)ので、試験では見つからなかった。
- 回避: 復元先の sshd に `HostKeyAlgorithms ssh-ed25519` を置いた。手順 3 の隔離の後は、復元先へは事業者のコンソールからしか入れない。今回はコンソールのパスワードの記録が無く、起動のメニュー(GRUB)から入って設定を置き、再起動した。
- 直し: していない(凍結中)。イテレーション 2 の入力にした。

## 言えること・言えないこと

- 言えること: 製品ビルドで、実機の 1 組に対して、導入の手順 1〜13、最初のバックアップ、別のサーバーへの復元テストが合格した。
- 言えないこと: 会話だけで進んだこと。人が端末や事業者のコンソールで手を入れた所が 5 つある(元サーバーの `acl` と一時的な sudo、元サーバーのファイアウォール、DB の権限、通知の受け口、手順 9 の欠陥の回避)。どれも、別に開いた Claude Code の助けで進めた。DB の論理ダンプが読み込めるかは、製品は確かめていない。
