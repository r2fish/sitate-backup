# 動画の撮影の予行(案 D。2026-11-05 の夜、監督。D-0208)

- ビルド: accept の worktree の `f9fa3d8`(測定 4 と同じ試験ビルド)。環境 `v6r`(変種 `add`、MinIO)。偽の LLM で `make test-app-e2e` を流した。A2 は終了コード 0「導入が完了し、機械で判定する項目を満たした」(約 2 分 24 秒)、A6 は終了コード 0「注入文をすべて入れ、応答を記録した」(約 7 秒)。環境は down 済み。製品のコードと `test/` は変えていない。
- 窓の見張り: 2 秒ごとに、画面上の窓の一覧(`CGWindowListCopyWindowInfo`)から Electron の窓の位置・大きさ・重なりの順と、前面のアプリを取った(窓の名前と中身は読まない)。72 回。

## 1. 窓が録画できる形で出るか

- 出る。ヘッドレスではなく、画面の外でもない。A2 の回の窓 1 つ(70 回)と A6 の回の窓 1 つ(2 回)が、どちらも x=185・y=98・1100×760 で画面の上にあった。回ごとに新しい窓になる(窓の番号が変わる)。
- 起動の直後は最前面(重なりの順 1、前面のアプリが Electron)。その後、ほかのアプリを前に出すと隠れた(重なりの順 2〜4 が 67 回)。予行の間は監督の録画の試み(下)が開いたシステム設定と、作業端末のほかのアプリが前に出ていた。撮影の間は、ほかのアプリを前に出さない。
- 監督のセッションからの録画(`screencapture -v`・`-l`)は、画面の録画の許可が無いため撮れなかった(`could not create image from window`。許可を求めるシステム設定が開いた)。許可は与えていない。撮影は利用者が自分の録画の道具で行い、許可はその道具に与える。録画の中身の確かめ(映り・文字の読みやすさ)は、この予行ではできていない。

## 2. 承認の画面の出ている時間

測定 4 の 3 回の記録(`test/acceptance/records/A2/m4/{1,2,3}/record.jsonl`)から、面の操作(`surface_op`)の時刻と、その前の出来事の時刻の差を取った。記録には面が開いた時刻が無いので、これは出ていた時間の上限。

| 面 | 上限(3 回) | 読めるか(見込み) |
|---|---|---|
| seal の承認カード(手順 10) | 5.3〜5.6 秒 | 普通の速さでは読めない見込み |
| 秘密の入力ボックス(LLM API キー、管理用鍵、保管先の管理用鍵、Webhook の URL) | 2.1〜5.3 秒 | 同上 |
| フレーズの確かめの入力ボックス | 0.5 秒 | 読めない |
| フレーズのパネル(手順 6。開いてから「控えた」まで) | 11.6〜20.0 秒 | 読める。ただし 24 語が映る(下) |

- 上限の中には、エージェントの応答を待つ時間が入っている。ドライバは 250 ms ごとに画面を見て、面を見つけたらすぐ入力して押す(`app/test/e2e/human.ts` の `#card`・`#secret`。承認カードの確認語は手順 4 の試験通知で先に届いている)。このため、実際に出ている時間は 1 秒に満たないと見込む。録画で測っていないので見込みとして書く。
- 普通の速さで読めないものは、録画にその面が写ったコマがあれば止め絵で見せられる。コマが無いか読めなければ、提出文書のセッションが案 C(測定 4 の記録と U3c の画面写し)で差し替える。
- フレーズのパネルには 24 語が出る。ドライバは語を隠さない(語を隠す命令 `mask` は画面写しの口だけにある。`app/src/testing/shots.ts`)。動画の環境のフレーズは使い捨ての環境のものだが、A7 では秘密の値として扱う。編集でぼかすか、その区間を使わない。

## 3. 入力の速さ

- 変える手は無い。ドライバの待ちは定数(`app/test/e2e/a2-loop.ts:17`・`a6-loop.ts:11` の `POLL_MS = 250`、頻度制限の待ち `RATE_WAIT_MS`)。ドライバが読む環境変数は `SITATE_ROLE_*` と `SITATE_FAKE_DECLINE_SRV`(偽の LLM の口の変種)だけで、速さに関わるものは無い(`app/test/e2e/*.ts` の `process.env`)。コマンドラインの引数にも無い。アプリに渡す環境は `launch.ts:67` の 6 つで固定。
- 設計の指示(D-0208 の追記)で、速さは条件から外れた。

## 4. 試験ビルドだけにあるもの(README の「使い捨ての署名鍵、試験の時計、接続先の読み替え」の 3 つの外)

読解は reader(全文の記録はリポジトリの外)。監督は根拠の行を開いて確かめた。

| 違い | 場所 | 動画に映る振る舞い |
|---|---|---|
| LLM の口がドライバの中継へ向く | `app/src/agent/entry.ts:29`、`app/src/testing/attach.ts` | 画面の部品と文言は変わらない。実物の LLM の回(`--mode real`)では中継が実物の API へ送る。応答は実物の LLM のもの。中継は送った内容を記録する(`test/acceptance/launch.md`「ドライバがすること」) |
| ドライバが画面を操作する(受け口 `SITATE_TEST_DRIVER_SOCKET`) | `app/src/testing/attach.ts`・`driver-server.ts`、`main/index.ts:87` | 入力とクリックはスクリプトで入る。マウスのカーソルは動かず、文字は 1 度に入る。人の役の答えはすぐに入る |
| 使い捨てのキーチェーン | `main/index.ts:105`、`app/src/testing/test-keychain.ts` | 変わらない(置き場だけ違う) |
| 画面写しの口(明暗の切り替え、フレーズの語を隠す) | `app/src/testing/shots.ts` | ドライバの A2・A6 の回はこの命令を送らない。映る振る舞いは変わらない |
| 核の上限・猶予・記録の締め切り・state.lock の待ちを環境変数で短くする | `internal/cli/testbuild.go` の `limitsFromEnv`(`SITATE_TEST_RUN_MAX_DURATION_S` ほか 3 つ) | 受入試験の環境はこの 4 つを置かない(`test/env/bin/accept-env.sh` に無い)。変わらない |
| 核の `test-tick` サブコマンド、`version` の `format_versions.test`・`sim_time` | `internal/cli/testtick.go`・`testbuild.go` | A2・A6 のドライバの回は使わない(`test-tick` は A6 の CLI の回の時刻を進めるときだけ) |
| アダプタへ渡す環境(`SITATE_TEST_B2_AUTH_URL`、`SITATE_EXTRA_CA_FILE`) | `internal/adapter/testenv_testbuild.go` | B2 の認証先の差し替えは試験だけで使い、受入試験の環境は置かない。追加の CA は通知の受け手(試験の環境の `hook`)の TLS に使う。画面は変わらない |

ビルドではなく環境の違いで、動画に映るもの:

- 通知の受け手は試験の環境の `hook` のコンテナ(実物のメールやチャットではない)。承認カードの確認語は、ドライバがそこから読んで入れる。
- 場面 6(A6)の保管先は試験用の MinIO で、B2 ではない。`seal` までの状態は偽の LLM で作る(測定 4 の A6 と同じ)。
- 元サーバー・バックアップサーバー・復元先は、作業端末の上のコンテナ(合成データ)。

読んだ範囲: `app/scripts/build-app.mjs` の全体、`app/src/main/index.ts` の 40〜110 行、`app/src/agent/entry.ts` の 10〜40 行、`app/src/testing/` の全体、`app/test/e2e/launch.ts` の 55〜90 行と `human.ts` の面の処理、`sitate_testbuild` の付いた Go のファイル 9 つ(`testtick.go`・`testtick_days.go` は冒頭だけ)、`tools/build.sh` の 19〜40 行。`grep` で `__TEST_BUILD__`・`SITATE_TEST_` が `app/src` で上の場所の外に無いこと、`sitate_testbuild` の付いた試験でない Go のファイルが上の 9 つだけであることを確かめた。

確かめていない範囲: 画面のコード(`app/src/renderer/`)に試験ビルドだけの分岐が無いことは `__TEST_BUILD__` の検索だけによる(束ねの `define` の外の分岐は読んでいない)。`test-tick` の本体。ドライバの中継の本体(`app/test/e2e/llm-endpoint.ts`)。試験の環境の既定値(遅延の時間、保持の日数)が画面の表示に出る値。録画した映像そのもの。
