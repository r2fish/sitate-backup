## 実物と偽物(代役)の別

実物: `sitate` のバイナリ(試験ビルド)・`gate`・SSH(各ホストの実 sshd、核の `SSHClient`、台本の `x/crypto/ssh`)・署名の検証(試験の鍵)・root でない `sitate` ユーザー・rootless の podman・systemd `--user` と linger・MinIO・元サーバー(source-setup の実行)・復元先(`ssh-host`)・`Recorder`・`StateFiles`・`Secrets`・`Notifier`。

代役・迂回(台本の中にあり、下の「見つけたもの」と対応する):

| 代役 | 理由 |
|---|---|
| 保管先準備アダプタ `b2` の `adapter.json` を `test/mainpath/provminio`(`check` だけ答える)へ差し替え | 同梱の `b2` は B2 の API にしか届かない。`bucket check` が権限の読み取りに `check`(枠 `key`)を呼ぶ |
| 保管先の鍵(`secrets/storage.json`)を台本が置く | `init-storage` は `bucket check` が master 鍵の無い状態で INTERNAL になり通せない(E3)。`secrets set` はイテレーション 3 |

## 見つけたもの

実装の誤り:

- E1 `adapters/provision/b2/adapter.json` と `adapters/notify/webhook/adapter.json` の `secrets` が `[]`。核は宣言に無い枠を要求から落とす(`internal/adapter/request.go`)ので、`admin`・`key`・`url` の枠がアダプタに届かない。再現: 試験用アダプタを `secrets: []` で置くと、`ADMIN_SLOT_MISSING`(`ADAPTER_ERROR`)で止まる(`init-storage`)。実際の B2 と通知の Webhook は動かない見込み(実物の B2 と Webhook は未検証)。
- E2 `internal/keys` の `KeyService.IssueKeys` が `--adapter` を使わず `ProvisionName`(既定 `b2`)を呼ぶ。`init-storage` は `--adapter` を必須にしているのに、鍵の発行だけが別の名前を呼べる。
- E3 `phrase verify` の確定と `init-storage`・`bucket check` の `write_intent` の記録が、`keys/master.json` を要する `Recorder` の journal 鍵で INTERNAL(`keys`)になる。master 鍵は確定の最後まで `keys/pending/master.json` にあるため。仕様の順(`init-storage` → `init` → `phrase verify`)でも、`init` の後でも通せない。実 CLI の導入が `init` → `phrase verify` で止まる。スタック: `Recorder.appendLocked` → `KeyService.DerivedKey` → `loadMasters`。
- E4 `acquire.Ingest`(`internal/acquire/run.go`)が承認済みの定義だけを読み、`seal` の前の `backup` が `NOT_SEALED`。仕様(3.1.2.1・3.6)は取得を `seal` の前も止めない。
- E5 `init` が登録する systemd の単位に `LimitCORE=0`・`LimitMEMLOCK=infinity` が無い(仕様 3.1.1「鍵のメモリ」・7.5 `Timers`)。単位は `ExecStart=-…` で、核の失敗が systemd の結果に出ない。
- E6 `bucket check` が保管先準備アダプタの `check` を常に呼ぶ。アダプタの無い事業者(仕様 3.2.6「判定できない場合」で `untested`)の経路は、置き場に `b2` が無いと INTERNAL(`adapter`)で、実装されていない。

契約の不足:

- C1 `bootstrap.ts` の段 (4) は動いているホストの `<os>-<arch>` の分だけ置くが、`phrase verify`(`keys.binFiles`)は保管先の `bin/` へ写すために版ディレクトリの両方の arch・ソースのアーカイブ・SBOM を要る。そのまま導入したホストでは `phrase verify` が INTERNAL になる。
- C2 `tools/sign.sh` はアダプタの実行ファイルに署名しない(仕様 3.2.1)が、アプリの `bundle-load.ts`・`build-app.mjs` と `bootstrap.ts` の `place` は同梱の全ファイルに `.sig` を要る。`make build-app` が `unsigned` で止まる見込み(`build-app.mjs` の読みによる。実行は未確認)。

仕様の穴:

- S1 `def validate` が参照名の解決を行うが、`storage[0].key_ref` は `init-storage`(手順 5)で、`restore.dest.key_ref` は `restore-dest enroll`(手順 9)で初めて存在する。手順 4 の `def validate` は必ず `unresolved_ref` になる。
- S2 手順 5 の `bucket check` は引数なしと書くが、`seal` の前は `--key-ref` が既定を持たず `ARG_INVALID`(`missing`)。
- S3 `secrets set` がイテレーション 3(`NOT_IMPLEMENTED`)のため、イテレーション 1 では B2 以外の保管先に鍵を置く手段が無い(`init-storage` は B2 の管理用鍵が前提)。

試験の誤り: 本段では見つけていない。
