- 対象: `U1a`、`U1b`、`U1c`、`U1e`、`U1g`、`U1f-0`、`U2a` の受け入れ済みの実物(main、`370b410` の時点)。
- コマンド: `make test-env-up NAME=mainpath` の後に `SITATE_NESTED=1 make test-mainpath STAGE=1 NAME=mainpath`。監督が 3 回実行し、すべて `ok`(約 9 秒)。

| 試験 | 確かめたこと |
|---|---|
| `TestStage1BackupRestoreMatchesSource` | 通常、0 バイト、ディレクトリ、シンボリックリンク、日本語の名前、40 MiB のファイルを backup して空のディレクトリへ restore。元データから計算したハッシュ、サイズ、モード、mtime、リンク先、余分と欠けが一致 |

| `TestStage1WrongSnapshotKeyCannotDecrypt` | 別のスナップショット鍵で復号できない |
| `TestStage1RetentionExtendAndPrune` | `Extend`、`Prune`(期限前なので消さない)、`Verify`、その後の restore |

実物: 実際の MinIO、rootless podman の容器、実物の `Verifier`(使い捨ての鍵)。偽物: `Secrets`、`StateFiles`、`Recorder`、`RetentionParams`。`SSH` はハーネスの小さな実装で受け口をローカルに起動する。

## 部品を壊して赤になること(監督が実行)

- 赤: 復元のモードを固定にする、復元の時刻を当てない、チャンクの展開を飛ばす。ハーネスを書いた担当の記録では版指定なしの読み出しも赤。
- 緑: チャンク ID の鍵を 0 にする。書く側と読む側が同じなので通しでは見えない。`keys` の試験が確かめる。

## 見つけた食い違い

部品の実装の誤りは出なかった。

- `Encode` の見出しの要件が契約に書かれていなかった(契約の注釈に足した)。
- `run.go` の `Ingest` のコメントの `Acquire.Selftest` は存在しない(`preflight` の中で行う)。
- 仕様の穴: restore はデータのチャンクの版 ID をエントリの `ranges` から取り、鍵表の `v` を使わない。鍵表の `v` だけが違う世代を検知しない。

## 確かめていない範囲

実物の `SSH`、`sitate` の CLI の経路(第 2 段)、`Keys.InitStorage`、`RunCleanup`、`RestoreTest`、`List`、期限後の `Prune` の実削除、非 UTF-8 の名前、`partial` の世代、B2、DB の対象。`latest` の選択は `LastModified` の秒の精度に依る(1 秒以内に 2 世代できたときは未確認)。
