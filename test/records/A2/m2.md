## 1 回目(a2r4・add)

- 終了コード 1「台本に無い人の作業で止まった(同じ依頼の繰り返しで、道具を呼ばない)」。301 秒、LLM の要求 45。合格した手順は 1〜7 と 9、未合格は 8 と 10〜13。A7-1 は一致 0 で PASS(`state_values=8`。手順 8 で止まったため値が少ない)。
- 原因(製品): エージェントが定義の `source.host` に `ssh://<user>@source:22`(`--host` と同じ URI)を書いた。`def validate` は通し(`internal/state/validate_source.go:20` は必須の文字列としか見ず、契約のスキーマ `cli/common.json#/$defs/host` の pattern を当てていない)、`source enroll` は `--host` の `<host>`(`source`)と `source.host` を文字列で比べて `DEF_INVALID`(`/source/host`、`invalid_value`、`next` は空)を返した。モデルは原因を直せず、元サーバーの別の接続先を人に求めて止まった。その後の `source check` は `SECRET_MISSING`。
- ドライバ: 元サーバーの接続先を求める問いを Q3(復元先)と照合し、Q3 の答えを返した(D-0185 の B と同じ種類の照合の不具合)。

- 夜の洗い出しの (a)(bucket check の `NOT_INITIALIZED`)と (b)(init_storage の dry_run の `ARG_INVALID`)は出ていない。(c)(source enroll の `ARG_INVALID`)は出ず、`DEF_INVALID` は上の別の原因で 2 回。
